# codex — Codex CLI как субагент

**Роли.** Claude — дирижёр: режет работу, пишет задание, проверяет результат, решает. Codex — исполнитель: делает одно задание в своей сессии и отдаёт итог. Архитектура, решения, итог владельцу — у Claude.

**Контексты не смешиваются — в обе стороны.**
- Codex не видит переписку: задание — самодостаточный файл. Не «как мы обсуждали», а что сделать, где, как проверить, чего не трогать.
- Claude не тащит ход работы Codex: весь поток событий уходит в `<задание>.log.jsonl`, наружу — только итоговое сообщение. Журнал читать только при сбое, точечно (`grep`, `tail`), не целиком.
- Обёртку-агента на Claude для вызова не заводить: это лишний посредник и лишний расход. Вызов — прямо `run.sh` через Bash, долгий — с `run_in_background`.

## Брать ли Codex — спросить владельца

Подписка временная: Codex может пропасть в любой день, и работа не должна на нём держаться.

1. Перед первым поручением в сессии — `run.sh --check` (вход + лимит, лимит не тратит).
2. Codex доступен → **спросить владельца одной строкой**: «Отдать Codex (лимит N %): <что>? Или своими агентами?». Ответ действует до конца сессии; «да» на одно задание не означает «да» на все, если владелец так не сказал.
3. Codex недоступен (401, нет входа, лимит ≥ 80 %, `run.sh` упал) → не чинить молча, а сказать одной строкой и сделать то же своими субагентами (`ispolnitel` / `razvedchik` / `myslitel`). Задание пишется одинаково для обоих — переписывать не придётся.

## Codex долгий — только параллельно

Один запуск — от полуминуты до десятков минут. Поэтому:
- каждый `run.sh` — через Bash с `run_in_background: true`, Claude тем временем делает своё;
- независимые задания — пачкой в одном ответе, каждое в свой worktree (`git worktree add ../<репо>-cx-<тема> -b <ветка>`);
- ждать уведомления о завершении, не опрашивать журнал.

## Вызов

```bash
# 1. задание — в файл в scratchpad (не в репозиторий)
# 2. запуск (в фоне)
bash ~/.claude/skills/codex/run.sh <папка-репо> <файл-задания> [усилие] [модель] [песочница]
```

- модель по умолчанию `gpt-6.1-sol`: по каталогу OpenAI (`codex debug models`) — «последняя рабочая модель для кода», первая по приоритету, «почти уровень Astra дешевле», окно 500 тыс. токенов. `gpt-6-astra` — самая сильная, но заметно дороже по лимиту и с окном 272 тыс.: только по слову владельца. `gpt-6-luna` — дешёвая для простого. `gpt-6-sol` — прошлое поколение, не брать;
- усилие `low` (по умолчанию — у Sol так стоит и в каталоге OpenAI) | `medium` | `high` | `xhigh`. `low` — правка по готовому плану, перенос, тесты по образцу; `medium` — обычная задача, где надо разобраться в коде; `high`/`xhigh` — трудный баг, когда `medium` не справился. Повышать усилие, а не менять модель на Astra;
- `run.sh` отключает Codex лишние инструменты (свои агенты, браузер, экран, память, плагины) — вход меньше, работа быстрее; остаток ~12 тыс. токенов — встроенное задание самого Codex, его не убрать;
- песочница: `workspace-write` (по умолчанию: пишет только в папке, сеть закрыта), `read-only` (разведка, второе мнение), `full` (без песочницы — нужно, когда задание ходит в сеть, по ssh, в базу; включать осознанно);
- `run.sh` печатает итог Codex, время, токены и проценты лимита Codex до/после.

## Как писать задание

1. Цель одной фразой.
2. Файлы и места (пути, функции), с которых начинать.
3. Правила репозитория, которые важны именно здесь (Codex сам прочтёт `AGENTS.md`/`CLAUDE.md` не всегда — нужное повторить).
4. Чего не трогать.
5. Как проверить (команда сборки/теста).
6. Формат итога: «в конце: что сделано, какие файлы, что проверено, что не получилось» — коротко.

## После итога — проверка обязательна

Итог Codex — непроверенный ввод. Смотреть `git diff` (или `git -C <worktree> diff`), прогонять проверку самому, только потом принимать. Коммит делает Claude, если владелец просил коммитить.

## Лимит Codex — следить

```bash
node ~/.claude/skills/codex/limits.mjs
# {"ok":true,"plan":"prolite","windows":[{"kind":"week","percentUsed":3,"resetsAt":"..."}]}
```

Лимит не тратится (запрос к `codex app-server`, `account/rateLimits/read`, ~2 с). У тарифа `prolite` одно окно — неделя; у других может быть ещё 5 ч.

- **До задания** — проверить; за 80 % по любому окну — не запускать, спросить владельца.
- **Во время долгой работы** (серия заданий, фон дольше ~15 мин) — проверять между заданиями.
- **По завершении** — в отчёт владельцу строкой: «Codex: N заданий, время, лимит было X % → стало Y %».

Свой лимит Claude и лимит Codex постоянно видны в полосе над вводом (мод `limits-band`): проценты обоих, время и прирост процентов последнего хода, какие скиллы и агенты в нём работали.

## Грабли

- `401 Unauthorized` — вход протух или другой аккаунт: владелец делает `codex logout` → `codex login` в терминале (браузер), Claude этого сделать не может.
- Нет модели в `codex debug models` — аккаунт не тот (видно по `plan` в `limits.mjs`).
- Предупреждение «ignoring unrecognized configuration settings» — в `~/.codex/config.toml` устаревшие ключи; песочница задаётся `sandbox_mode`, не таблицей `[sandbox]`.
- В `workspace-write` закрыта сеть: `go mod download`, `npm i`, ssh, база — падают. Для таких заданий `full` или подготовить зависимости заранее.
