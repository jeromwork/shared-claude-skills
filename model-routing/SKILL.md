# model-routing

Держать стоимость сессии под контролем, не теряя качества там, где оно нужно.

**Главный расход — не модель, а объём контекста.** Всё, что прошло через
главную сессию, переотправляется на каждом следующем шаге; за длинную сессию
это растёт быстрее, чем разница в цене между моделями. Поэтому порядок
приоритетов: сначала §4 (не тащить лишнее в контекст), потом §2 (уводить
чтение в подагента), и только потом §3 (просить сменить модель).

**Что именно жрёт контекст — порядок величин.** Правило экономии должно бить
по крупному, а не по мелкому:

| Источник | Вклад за один раз |
|---|---|
| Реплика оператора + текстовый ответ | 200–800 токенов |
| `Read` файла на 400 строк | ~6 000 |
| `Grep` с `output_mode: content` по каталогу | 3 000–15 000 |
| Ответ внешнего инструмента (list / query / дамп схемы, MCP или API) | 5 000–40 000 |

Вывод: **обсуждение дешевле вывода инструментов в 10–50 раз.** Экономить на
формулировках и «покороче отвечать» — мимо. Экономия живёт там, где в контекст
льётся вывод инструментов, — и лечится это подагентом (§2) и гигиеной (§4).
Длинное обсуждение подагентом не лечится вообще — лечится §4.1.

## 1. Что можно, а что нельзя

| | Кто делает | Механизм |
|---|---|---|
| Сменить модель **главной** сессии | **только оператор** | `/model claude-sonnet-5` в строке ввода |
| Запустить работу на **дешёвой** модели | **Claude, сам** | `Agent(model: "sonnet" \| "haiku")` |
| Сбросить контекст | **только оператор** | `/clear`, `/compact` |
| Снизить effort | **только оператор** | `/model` → `Effort` |

Отсюда правило: **что можешь сделать сам — делай молча, о чём просить нужно —
проси одной строкой и не настаивай.** Не превращай экономию в переговоры;
предложение сменить модель — одна фраза в конце ответа, не отдельный ход.

**Возможный блокер харнесса.** Некоторые сборки Claude Code кладут в системный
промпт строку вида «Do not call the AgentTool unless the user requested it». Она
сильнее этого skill: пока она есть, §2 не работает — подагент не поднимается без
явной просьбы оператора. Живёт она в сборке, а не в файлах настроек, поэтому
правкой `settings.json` или `CLAUDE.md` её обычно не снять. Если видишь эту
строку у себя в промпте — не молчи: одной фразой сообщи оператору, что
делегирование заблокировано на уровне харнесса, и дальше спрашивай перед каждым
подагентом. Не притворяйся, что делегируешь, когда не можешь.

## 2. Уводить в подагента на дешёвой модели (делается само, без спроса)

Подагент работает в **своём** контексте и возвращает короткий вывод. Экономия
двойная: дешёвая модель + главный контекст не растёт.

### 2.0 Дефолт — делегировать

**Чтение делегируется по умолчанию, а не по достижении порога.** Не ждать, пока
контекст наполнится: заполненность — плохой триггер, к моменту её срабатывания
дорогой вывод уже в контексте, и оттуда он не убирается. Дешевле держать
привычку постоянно, чем включать её ситуативно.

Решение принимается **одним вопросом**: нужен ли этот вывод в главном контексте
дословно и дальше по ходу работы?

- **Нет** → подагент. Даже если это «всего пара grep'ов» — вернётся 20 строк
  вместо 400.
- **Да** → делать самому.

**Закрытый список исключений — только здесь делаем сами:**

1. **Нужен дословный материал для правки.** Файл, который сейчас будем
   редактировать; дифф, который идёт в коммит; точный текст ошибки. Подагент
   вернёт пересказ, а править надо по букве.
2. **Нужен накопленный контекст сессии.** Обсуждали час, решения принимались по
   ходу — брифинг подагенту выйдет длиннее самой работы.
3. **Ответ уже известен, проверка одноразовая.** Один `Read` по точному пути,
   одна проверка `git status`, один `curl`. Тут подъём подагента дороже.
4. **Работа пишущая.** Правка кода, коммит, миграция — §2 про чтение, не про
   запись.

Всё остальное — «где определён», «где используется», «что в этом логе», «есть ли
в кодовой базе уже такое», «что возвращает этот инструмент», «просканируй
каталог» — уходит в подагента без вопросов и без объявления. Отчитываться
оператору о самом факте делегирования не нужно, нужен результат.

### 2.1 Какой подагент и какая модель

Решает **не тип работы, а тип критерия поиска**: буквальный он или его надо
угадать.

| Работа | `subagent_type` | `model` |
|---|---|---|
| Свип по известному символу/строке/шаблону: «найди все вызовы `foo()`», «где ещё встречается эта константа» | `Explore` | `haiku` |
| Собрать список файлов/вхождений по механическому критерию | `Explore` | `haiku` |
| Вычитка текста, перевод, переименования по образцу | `general-purpose` | `haiku` |
| Концептуальный поиск: «где выбирается реализация по конфигу», «как устроена авторизация» — нейминг надо угадать | `Explore` | `sonnet` |
| Разбор большого лога, вывода сборки, дампа | `general-purpose` | `sonnet` |
| Проверить гипотезу, требующую чтения 3+ файлов | `general-purpose` | `sonnet` |

**Граница Haiku ↔ Sonnet.** Haiku исполняет поиск, но плохо его *формулирует*.
Если критерий задан буквально (символ, строка, glob) — он справляется, и
результат проверяем: это пути и номера строк, промах видно. Если нужно вывести,
как искомое может называться в коде, — Haiku вернёт пустоту, и это **молчаливый
ложноотрицательный результат**: вы не узнаете, что он искал не то слово. Такой
поиск — на Sonnet.

### 2.2 Нарезка: короткие подагенты, а не «разберись с темой»

Подагент не должен зависать надолго — длинный подагент теряет фокус, жжёт квоту
и всё равно возвращает размытый ответ. Нарезка:

- **Один подагент = один вопрос с проверяемым ответом.** «Где регистрируются
  CLI-команды» — да. «Разберись, как устроена эта подсистема» — нет, это три
  вопроса.
- **Бюджет — 5–10 вызовов инструментов.** Не уложился — виновата не модель,
  а формулировка: вопрос был слишком широкий, режь ещё.
- **Независимые вопросы — параллельно, одним ходом.** Три подагента в одном
  сообщении идут одновременно; три подряд — тройное ожидание на ровном месте.
- **Не строить цепочки.** Если ответ второго зависит от первого — обычно это был
  один вопрос, разрезанный не по тому шву.

**Return contract — писать в каждом промпте, без него экономия испаряется:**

```
Верни ≤ 30 строк: `file:line` + одна строка роли. Без пересказа файлов,
без вступления и заключения. Не нашёл — напиши это одной строкой.
```

«Расскажи, что нашёл» возвращает простыню на 3 000 токенов — ровно то, от чего
уводили. Проси **вывод, а не пересказ**.

## 3. Фазы работы → модель главной сессии

Предлагать смену **на границе фаз**, а не посреди работы.

| Фаза | Модель | Почему |
|---|---|---|
| Непонятная проблема, диагностика с нуля, архитектура, спорное решение | **Opus 5** | цена оправдана: ошибка здесь стоит дороже модели |
| План утверждён, идёт реализация по нему | **Sonnet 5** | решения приняты, остаётся аккуратно применить |
| Механика: переименования, форматирование, правки по образцу, рутинные коммиты | **Haiku 4.5** | нюансов нет |
| Разбор логов, поиск по коду, сводки | — | не менять модель, увести в подагента (§2) |

**Момент, когда обязательно предложить переключение:**

- План согласован и переходим к коду → «План зафиксирован. Дальше механика —
  `/model claude-sonnet-5` сэкономит; вернуться `/model` → Default.»
- Пошла новая, не связанная с предыдущей тема → предложить сброс (§4.1):
  это сильнее смены модели, потому что обнуляет накопленное.
- Sonnet буксует — второй раз подряд не улавливает суть, предлагает неверное →
  сказать прямо: «это уже не механика, верните Opus», без попыток дожать.

**Не предлагать переключение**, если до конца задачи явно пара шагов —
переключение туда-обратно само по себе не бесплатно и сбивает работу.

## 4. Гигиена контекста — самый крупный рычаг

Действует всегда, независимо от модели.

### 4.1 Сброс накопленного: `/clear`, `/compact` или выписать в файл

Подагенты не дают контексту расти, но уже накопленное они не убирают. Убрать его
можно только сбросом, и вариантов три. Выбирает **оператор**, предлагает Claude —
одной строкой, с уже выбранным вариантом, а не списком.

| Ситуация | Что предложить | Почему |
|---|---|---|
| Новая тема, от предыдущей ничего не нужно | **`/clear`** | обнуляет полностью и стоит ноль токенов |
| Та же задача продолжается, нить терять нельзя | **`/compact`** | сохраняет решения, но сам платит проходом по всему контексту — тем дороже, чем позже вызван |
| Долгая задача, впереди объёмная фаза, итог важен дословно | **выписать итог в файл → `/clear`** | «ручной компакт»: контролируешь, что уцелело, и дешевле авто-сжатия |

Третий вариант — рабочая лошадка для длинных задач: попросить Claude выписать
состояние (решения, что сделано, что осталось, ключевые пути) в файл в
скретчпаде, затем `/clear`, затем прочитать этот файл в новой сессии. Один `Read`
на 60 строк вместо десятков тысяч токенов истории.

**Когда предлагать:** на смене темы и на границе фаз (§3) — там же, где
предлагается смена модели, одним предложением. **Не** посреди отладки: сброс
контекста на середине диагностики стоит дороже, чем сэкономит.

**Заранее, а не по факту.** `/compact` в конце тяжёлой сессии — самый дорогой его
вариант: сжимать придётся всё разом. Автосжатие по достижении порога — не план,
а страховка: если оно сработало само, значит момент упустили.

### 4.2 Мелкая гигиена

- **Не дампить.** `tail -20`, `grep` с `-C 2`, `head_limit` — вместо полного
  вывода. Полный лог в контексте не нужен ни разу: нужна строка с ошибкой.
- **Читать файл кусками.** `offset`/`limit`, когда нужен один метод, а не
  файл на 800 строк.
- **Не перечитывать.** Файл, который уже читали и сами же правили, повторно
  читать не нужно — Edit сообщил бы об ошибке.
- **Не пересказывать свой же вывод.** Таблица из предыдущего сообщения не
  нуждается в повторе.
- **Запросы к данным — сразу с проекцией.** Выбирать нужные поля, а не всю
  строку на сорока колонках.
- **Один вопрос — один заход.** Собирать независимые проверки в один вызов
  вместо пяти последовательных.

## 5. Грабли

1. **Haiku на задаче с нюансами дороже Sonnet.** Переделка съедает всю
   экономию. Haiku — только там, где ошибиться негде.
2. **Смена модели посреди длинной сессии не обнуляет контекст.** Переключение
   на Sonnet в конце тяжёлой сессии почти ничего не даст: контекст уже большой,
   и он поедет с вами. Экономия появляется, если переключиться **до** объёмной
   фазы, а ещё лучше — вместе со сбросом (§4.1).
3. **Дробить один вопрос на пять подагентов — дороже, чем один подагент.**
   Каждый поднимает контекст с нуля. Это не про «делегировать реже», а про
   «резать по швам»: пять подагентов на пять *разных* вопросов — нормально и
   идёт параллельно; пять на один вопрос — ошибка нарезки (§2.2).
4. **`fork` игнорирует `model`.** Форк всегда наследует модель родителя —
   для удешевления он бесполезен, нужен обычный подагент.
5. **Не экономить на диагностике.** Цепочка, идущая через несколько слоёв
   (логи → БД → контейнер → системный сервис → флаги монтирования), дешёвой
   моделью не вытягивается: она выдаёт правдоподобный, но неверный вывод, и
   день уходит впустую. Диагностика с нуля — тяжёлая модель, без вариантов.

## 6. Смежное

- Расход и остаток квоты — `Account & usage…` в меню Claude Code.
- `/usage-credits` **не включать**: это оплата сверх плана, обратное экономии.
- Fast mode дороже обычного Opus — включать сознательно, не «чтобы быстрее».
- **Deep research этот skill не трогает.** Глубокое исследование, разбор
  архитектуры, prior art, живой веб — правила прежние: тяжёлая модель и
  [`delegate-to-agent`](../delegate-to-agent/SKILL.md) /
  [`delegate-web-research`](../delegate-web-research/SKILL.md), оператор
  запускает их отдельно и сознательно. Удешевлять их не пытаться — проверено,
  выходит дороже. Здесь речь только о механическом чтении и поиске внутри
  сессии.
