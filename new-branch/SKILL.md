# new-branch

Создать git-ветку по личному паттерну нейминга пользователя (g.jeromwork).

## Паттерн нейминга

```
j_<scope>_<краткое_описание_snake>_<DD_MM_YY>
```

- **`j_`** — обязательный префикс (инициал пользователя)
- **`<scope>`** — опциональный модификатор: `fix`, `ai`, `flow`, и т.п. Для багфиксов всегда `fix`. Для фич — можно опустить или использовать тематический префикс (`ai`, `catalog`, `clinic` и т.п. — по содержанию).
- **`<краткое_описание_snake>`** — 2–5 слов через `_`, описывают суть изменения, не PR-ный целиком, а файл/фичу/баг.
- **`<DD_MM_YY>`** — текущая дата, день/месяц/год по 2 цифры, через `_`. Брать СЕГОДНЯШНЮЮ дату, не дату обсуждения и не дату коммитов.

## Примеры из истории пользователя

- `j_fix_min_price_priority_26_05_26` — багфикс приоритета min_price
- `j_fix_near_work_day_26_05_26` — багфикс near_work_day
- `j_doctors_list_service_03_02_26` — фича сервиса списка докторов
- `j_ai_pages_generator_08_05_26` — AI-фича
- `j_catalog_24_04_26` — работа по каталогу
- `j_paykeeper_26_04_26` — интеграция Paykeeper
- `j_nginx_cache_12_03_26` — кэш в nginx

## Алгоритм

1. **Получить сегодняшнюю дату** в формате `DD_MM_YY`. Использовать `date +%d_%m_%y` в Bash, либо взять из `currentDate` в системном контексте.
2. **Определить scope**:
   - Если работа — это исправление бага/просадки/регрессии → `fix`.
   - Если работа — новая фича/интеграция/рефакторинг → опустить scope или подобрать тематический префикс (по основному модулю: `ai`, `catalog`, `clinic`, `flow`, …).
3. **Сформулировать `<краткое_описание>`** на английском, snake_case, без артиклей, без глаголов «add/fix» (scope уже это передаёт). 2–5 слов, ёмко описывают объект изменения (имя модуля/сервиса/фичи).
4. **Перед созданием** показать пользователю предлагаемое имя и **дождаться подтверждения**, если пользователь не дал имя напрямую и не сказал явно «создай не спрашивая». Можно предложить 2–3 варианта, если есть сомнения по описанию.
5. **Создать ветку** от текущей (или от `main`, если пользователь указал) командой `git checkout -b <name>`.

## Важно

- Дата всегда сегодняшняя на момент создания ветки, **никогда** не от даты обсуждения или прошлой ветки.
- Не использовать дефисы `-` внутри имени — только подчёркивания `_`. Пользователь иногда отступает от этого (например, `j_clinic_lat_lon_float_250526` без разделителей в дате), но дефолт — `_` везде.
- Описание — на английском, в нижнем регистре.
- Если пользователь дал явное имя — использовать его как есть, паттерн не навязывать.
